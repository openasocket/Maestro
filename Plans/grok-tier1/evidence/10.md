### Defect repaired

`getSessionDetail` (the source of `GET /api/session/:id?tabId=` and of the
`send_command` busy check) returned the logs of the resolved tab beside the agent-level
`session.agentSessionId`. The renderer's session-id listener
(`useAgentSessionIdListener.ts`, the success branch) writes the agent-level field for
every non-Claude provider on every capture, so for a Grok agent it is whichever tab last
received its end-only native session id. With two Grok tabs, the detail of tab A named
tab B's conversation; a fresh Grok tab whose `end` had not arrived named a sibling's id.
The callback now reports the resolved tab's own `agentSessionId` (null, sent as absent,
when that tab has none yet or when a requested tab is missing) and keeps the agent-level
field only for an agent with no AI tabs. Provider-generic: Claude (whose agent-level
field is never refreshed) gets the same honest answer.

### Change

- `grokQuestionGapOf()` and `grokQuestionGapMessage()` moved from the desktop spawner into
  the shared driver (`grok/acp-turn.ts`, exported through the library index), one rule for
  every host. The spawner imports them; its behaviour is unchanged.
- `startGrokAcpTurn` records the first question its own turn settled unanswered (stale
  requests for another session or turn are ignored, as before). When that question's
  terminal is the one that settled the turn (no later stop or failure), the completed turn
  reads outcome `crashed` with an `AgentError` (`type: unknown`, `recoverable: false`,
  `agentId: grok`) carrying the same words the desktop tab shows. The terminal stays the
  protocol fact (`cancelled`, `user-input-unavailable`). A user Stop still reads
  `interrupted`; a question never becomes a permission or a policy decision.
- Result: desktop, browser/Lite (mirroring the desktop) and headless callers read one
  truthful contract. No caller waits on an answer; an unattended run settles explicitly.

### Not changed (recorded)

- Pending questions, typed choices and responder authorization stay unimplementable: the
  pinned peer advertises no ask-back capability, so no pending event is ever emitted and
  no answer surface is added (blocker `acp-question-negotiation` unchanged). Identity is
  already carried per question (`questionId` over account, host, process generation,
  session, turn, method, request id).
- No library version bump (the contract forbids version bumps).

## GT1-10-06 IMPLEMENT: Grok prompt, quoting and remote launch planning

### Defects repaired

1. **Unpaired surrogates in prompt-file text.** Grok's prompt always travels as an owned
   ACP JSON `--prompt-file`. A prompt (or ordered text block) holding a lone UTF-16
   surrogate, which a truncated emoji paste produces, was encoded by `JSON.stringify` as a
   `\uD83D` escape that a strict native JSON reader rejects after spawn (an opaque failed
   turn), and a plain-text prompt file would have been written with the code unit silently
   replaced by U+FFFD. The file route now refuses such text before any artifact is planned
   (`prompt-delivery-refused`, fixed message, no prompt content in the diagnostic). Paired
   astral characters, newlines and every other well-formed string are unchanged. The argv
   and stdin routes of other providers are untouched.
2. **Control characters in the prompt-file destination.** Only NUL was refused. A CR, LF
   or other C0/DEL character in the host-chosen path would split the argument a Windows
   `.cmd` shim or the SSH script carries. Any `U+0000-U+001F` or `U+007F` now refuses
   the destination; host-chosen names (`maestro-prompt-<uuid>.json`) never contain one.

## GT1-10-09D IMPLEMENT: Grok stored history in getGlobalStats

Source-only, `src/main/ipc/handlers/agentSessions.ts` (+274 -7 after prettier). Consumes the GT1-10-09C cache contract; `statsCache.ts`, `types.ts`, preload and renderer unchanged.

### Gap

`agentSessions:getGlobalStats` scanned only `~/.claude/projects` and `~/.codex/sessions`, so Grok history never reached the About modal or shared achievements, and `aggregateProviderStats` priced any entry without `costUsd` through `calculateModelCost` (Claude rates), which would have turned an unknown Grok cost into an invented amount.

### Change

- Discovery (`discoverGrokSessionDirs`): account pools from the existing profile reader `getProviderAccountDirs('grok')` (configured agents, provider default, process env, `~/.grok`, `$HOME` scan; deduped by real sessions dir). The account scope is the realpath of the pool's `sessions` dir, so an alias selecting the same pool keeps the same keys and two pools never share one. Session dirs are fingerprinted by stat only (newest mtime of `chat_history.jsonl`, `usage.json`, `summary.json`; a missing or 0-byte transcript is skipped), bounded by `LOCAL_SESSION_READ_CONCURRENCY`. Keys are `qualifiedGlobalStatsSessionKey({ accountScope, projectPath: cwd, nativeSessionId })`.
- Reading: changed sessions are grouped by account and cwd folder and read through the registered storage, `getSessionStorage('grok').listSessions(cwd, undefined, accountDir)`, one folder at a time (the storage bounds its own per-session fan-out). Only results whose `projectPath` is that folder's cwd and whose ID is in the changed set are written. Tokens, cost, `usageSource` and `usageCompleteness` are the storage's own reading of `usage.json` (`grokCachedSessionStats`); no second parser, no pricing. An absent ledger stays `{ status: 'unknown' }`.
- Cache reuse and archive: an entry is re-read only when its fingerprint is newer than `fileMtimeMs`; a key no longer discovered is marked `archived` and still counted, as for Claude and Codex. A failed account discovery keeps every cached Grok entry as it was instead of archiving them all.
- Resumed histories: a resume loads the same native ID (same directory), and `usage.json` is a lifetime snapshot (`reporting: 'snapshot'`), so a re-read replaces the entry and never adds to it.
- Forks and subagents (`withoutParentAttributedUsage`): a session whose summary names a `parent_session_id` present in the same pool (archived parents included) keeps its session and messages but contributes no tokens and a partial cost with no amount, because a fork copies its parent's ledger and a parent folds its finished children; the total stays a floor, never an overcount. A parent absent from the pool leaves the child counted in full.
- Aggregation: Grok tokens via `aggregateProviderStats` (which now skips the legacy pricing fallback for any entry carrying `cost`); amount, `costUsdTicks` and `costCoverage` only from `summarizeCachedSessionCost`. `ProviderStats.hasCostData` is false when coverage is `unknown`, so an unknown cost is never shown as a free total. Once any provider reports coverage, `GlobalAgentStats.costCoverage` merges all providers through `mergeStatsCostCoverage`, counting a legacy provider with cost data (Claude) as covered and one without (Codex) as unknown; Claude/Codex-only payloads keep the legacy shape with no `costCoverage`.

### Projection compatibility (traced, read-only)

- `preload/sessions.ts` passes the IPC payload and `agentSessions:globalStatsUpdate` through unchanged, so `costCoverage` and `costUsdTicks` reach the renderer at runtime. Its `GlobalStatsUpdate` interface and the two inline `getGlobalStats` shapes in `renderer/global.d.ts` (lines ~2295, ~2623) do not declare the optional fields; `useGlobalAgentStats` types the payload as the shared `GlobalAgentStats`, which does. Whether About/achievements need the declared fields is GT1-10-09E's to decide; no continuation scheduled here.

### Limitations

- Local pools only, like Claude and Codex here: SSH-remote Grok history is not scanned by global stats.
- A changed session re-reads its whole cwd folder through `listSessions` (and that call also reads descendant folders, whose results are ignored here).
- A session the storage does not list (never prompted, unsafe folder name, unreadable) is re-read on every run, since nothing is cached for it.
- The parent rule is decided when the child is read; a parent first discovered after its child was cached does not revisit the cached child until the child changes.
- The storage marks every Grok cost partial (`cross-file-generation-unverified`), so Grok coverage reads `partial` or `unknown`, never `complete`, until a verified cross-file snapshot exists.

## GT1-10-10 Grok quota capability presentation

Verdict: no behavior change needed; the two seams already present Grok quota truthfully. Only documentation comments were added so the decision is visible at the code that would otherwise be extended.

- **No qualified Grok quota API.** Earlier evidence (01.md rows B25 and B43, GT1-04-11C, GT1-10-08) records no native Grok plan-quota, balance or reset contract and no provider abstraction for one. Nothing here consumes or invents a service call.
- **`useQuotaTabDiscovery.ts`:** samples only `refreshClaudeUsageSnapshots` and `refreshCodexUsageSnapshots`, once per open, behind the `usageStats` Encore flag. No Grok call exists, so an unsupported provider makes no HTTP request.

No such evidence exists, so no task is scheduled now; GT1-10-11 asserts the unsupported state.
