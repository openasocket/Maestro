### Defect repaired

`getSessionDetail` (the source of `GET /api/session/:id?tabId=` and of the
`send_command` busy check) returned the logs of the resolved tab beside the agent-level
`session.agentSessionId`. The renderer's session-id listener
(`useAgentSessionIdListener.ts`, the success branch) writes the agent-level field for
every non-Claude provider on every capture, so for a Grok agent it is whichever tab last
received its end-only native session id. With two Grok tabs, the detail of tab A named
tab B's conversation; a fresh Grok tab whose `end` had not arrived named a sibling's id.
The callback now reports the resolved tab's own `agentSessionId` (null, sent as absent,
when that tab has none yet or when a requested tab is missing) and keeps the agent-level
field only for an agent with no AI tabs. Provider-generic: Claude (whose agent-level
field is never refreshed) gets the same honest answer.

### Change

- `grokQuestionGapOf()` and `grokQuestionGapMessage()` moved from the desktop spawner into
  the shared driver (`grok/acp-turn.ts`, exported through the library index), one rule for
  every host. The spawner imports them; its behaviour is unchanged.
- `startGrokAcpTurn` records the first question its own turn settled unanswered (stale
  requests for another session or turn are ignored, as before). When that question's
  terminal is the one that settled the turn (no later stop or failure), the completed turn
  reads outcome `crashed` with an `AgentError` (`type: unknown`, `recoverable: false`,
  `agentId: grok`) carrying the same words the desktop tab shows. The terminal stays the
  protocol fact (`cancelled`, `user-input-unavailable`). A user Stop still reads
  `interrupted`; a question never becomes a permission or a policy decision.
- Result: desktop, browser/Lite (mirroring the desktop) and headless callers read one
  truthful contract. No caller waits on an answer; an unattended run settles explicitly.

### Not changed (recorded)

- Pending questions, typed choices and responder authorization stay unimplementable: the
  pinned peer advertises no ask-back capability, so no pending event is ever emitted and
  no answer surface is added (blocker `acp-question-negotiation` unchanged). Identity is
  already carried per question (`questionId` over account, host, process generation,
  session, turn, method, request id).
- No library version bump (the contract forbids version bumps).
