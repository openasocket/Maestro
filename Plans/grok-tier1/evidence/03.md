## Actual paths and consumer contract

- `src/shared/maestro-lib/protocol/rpc-requests.ts` exports `RpcRequestTracker`
  and `RpcTransportFailure`. This is the actual shared-core path, replacing
  DESIGN's proposed `protocol/json-rpc.ts` name. It imports no host or provider
  modules and owns increasing numeric IDs, pending requests, deadlines,
  synchronous write failures, settlement and the first transport-close reason.
- `src/shared/maestro-lib/codex/rpc-client.ts` delegates to that core. Its public
  classes and request options remain in place. JSON serialization, JSON-RPC
  envelopes, response-ID validation, protocol errors, notifications and
  server-request answers stay in this wrapper. The existing main-process
  compatibility re-export is unchanged.

GT1-03-01 must consume `RpcRequestTracker`, not recreate its pending map.
Construct it with a `(method, failure) => Error` formatter; call
`request<T>(method, writeRequest, timeoutMs?)`, where the writer receives the
allocated ID. After validating protocol responses, call `resolve(id, result)`
or `reject(id, method => error)`. Call `close(reason)` when the transport ends;
`isClosed` exposes that state. Notifications and permission decisions do not
belong to this core. Raw write failures let each wrapper choose its diagnostic
policy without forcing Codex's error strings onto ACP.

Pending registration precedes writing, so synchronous responses or close win
over a subsequent write exception. All settlement paths remove the entry and
clear its timer, including timer handle zero. Duplicate/stale responses return
false. Closed requests reject without writing and retain the first close reason,
including an empty string. Codex keeps its existing error classes, method/code/data,
messages, omitted undefined params and unchanged notification/reply behavior.
Its old private pending engine was removed rather than copied alongside the core.

### Actual paths and next-consumer contract

- `src/shared/maestro-lib/grok/acp-protocol.ts`: wire envelopes, initialization
  validation, fixed transport/request error classes and `AcpFrameDecoder`.
  Wire version 1 is independent of schema 0.11.4, crate 0.10.4 and candidate
  npm 1.0.70. Known capability shapes are validated; omitted defaults and
  nullable optional metadata are accepted. Unknown extension data is retained
  without granting support. Provider error codes are preserved, but arbitrary
  server error messages/data are excluded from diagnostic errors.
- `src/shared/maestro-lib/grok/acp-client.ts`: `GrokAcpClient` owns
  `initialize()`, `request()`, `notify()`, `feedStdout()`, `feedStderr()` and
  `close()`. Its writer receives one UTF-8 frame including LF. The host must
  feed raw stdout bytes, close on pipe loss/async write failure, and own
  process termination/admission. `onClose` fires once after pending requests
  reject; `bufferedBytes` and `stderrBytes` expose bounded state without text.
  No Electron, session state, UI or policy dependency was introduced.

Search covered shared/main RPC, framing and protocol modules. The shared
`RpcRequestTracker` supplies IDs, deadlines, write failure and one-time
settlement. `BufferedLineReader` was inspected but cannot enforce this
contract unchanged: it bounds only leftover UTF-16 tails after extraction and
silently drops oversize content. ACP instead checks each byte segment before
decoding, processes complete lines individually without a frame queue, and
rejects invalid UTF-8, malformed envelopes, stdout noise and oversized frames.
The configurable ceiling defaults to the pinned upstream **64 MiB including
LF**, on both input and output. Oversize output is refused before writing.
Stderr is counted only, never parsed or retained; hosts own any redacted log
sink. Unterminated EOF is an incomplete frame, not a successful final reply.

Initialization is single-flight, including synchronous writer/notification
reentry, and validates protocol 1 before enabling other outbound methods.
It sends empty client capabilities and no `initialized` notification. There
are no file, terminal or elicitation claims. Requests have a default 30-second
positive deadline with per-request overrides; timeouts never replay a request.
String, unknown, duplicate and stale response IDs cannot settle another
outbound request. Registered incoming methods receive the original ID and a
one-use response closure; unregistered methods receive fixed `-32601` errors.
Unknown notifications pass through opaquely. GT1-03-07/08A own incoming
request deduplication, session/turn ownership, deadlines, cancellation and
permission/user-input decisions; this layer does not claim those are enforced.

### Lifecycle and ownership contract

- `GrokAcpSession` composes `GrokAcpClient`, `createIdleWatchdog`, `stopProcess`
  and existing `SessionTurnRequest` fields. The host supplies an already
  admitted owned `ChildProcess`, its byte writer, selected account/host/cwd,
  and positive silence/hard-turn budgets. SSH hosts supply the existing
  guarded terminate operation. This module neither spawns nor authenticates.
- `open()` negotiates once, then sends exactly one `session/new` or advertised
  `session/load`. Load confirms the requested native ID without requiring an
  ID field in its response. A rejected load never becomes a new session.
  Confirmed identity survives model rejection, cancellation and a process
  exit immediately after the allocation reply. Tab IDs are never substituted.
- New allocation carries `_meta.modelId`; returned `models.currentModelId`
  and any model `configOptions` must acknowledge the selection before a
  prompt. Missing or contradictory acknowledgement is a refusal. A reported
  different cwd is refused. Actual account/environment binding remains the
  admitted launch owner's responsibility; account references are not wire
  authentication assertions.
- One prompt may be active per object. A process-local account/host/cwd/native
  ID claim also excludes duplicate resident objects until the owned process
  closes its pipes. Hosts retain cross-process serialization and lease cleanup.
- `prompt(text, signal)` returns the raw correlated response for subsequent
  terminal/usage normalization. Unknown stop reasons are preserved, missing
  reasons rejected; a returned object is not itself a claim of successful work.
  `onNotification` marks load replay separately from active-turn output.
- Cancellation before unsent setup prevents allocation. An already pending
  allocation gets a bounded chance to return its ID, with no prompt dispatch.
  After dispatch, send one `session/cancel` notification and await the original
  prompt settlement. A cancellation racing `end_turn` cannot become success;
  its raw response remains available for accounting. The cancel grace is not
  refreshed by output, whereas the ordinary silence budget is.
- Nonempty stdout/stderr refresh the shared silence watchdog; a separately
  configured hard-turn ceiling remains fixed. Process exit/error, pipe loss,
  timeout and explicit close reject pending work and use canonical termination.
  Keep the error listener and native claim through pipe close. Fixed lifecycle
  diagnostics retain safe transport causes and uncertain-dispatch provenance;
  there is no reconnect, route fallback or automatic prompt replay.
