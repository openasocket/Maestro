## Behavior observed (positive and negative)

- **Admitted child.** `turns.test.ts` "runs an admitted submission to
  completion": a real `node` process (the fake agent replaying a captured
  Claude Code turn) started under a lease, the journal attempt holds its pid
  and `lease-1`, the transcript holds the message, `inspect` answers
  `completed` with the captured session id, and `runs` lists it.
  `start-turn.test.ts` "admits a harmless launch": the gate saw
  `admit:ok`, `bound:number`, `released:0:none` in that order and the agent
  wrote its argv file.
- **Denied, zero effects.** `turns.test.ts` "denies with zero effect": the
  facade answers `denied / policy-denied` with the reader's reason; no argv
  file exists, the transcript is empty, no `started` event, the queue is
  empty, the journal attempt is `failed` with `managed-denied`; a standalone
  `turns.send` on the same runtime then runs. `start-turn.test.ts` "refuses
  a denied launch": `DispatchRefusedError`, `onStarted` never fired, the
  argv file does not exist, the authority holds no lease.
- **Changed plan.** `start-turn.test.ts`: a lease admitted on one spec
  refuses a spec with one changed argument (`snapshot-mismatch`) and the
  same spec under another provider attribution; the admitted spec then runs.
- **Stale and forged authority.** Expired, forged (a copied lease),
  already-bound and released leases are refused at the spawn; a context from
  another installation, a malformed context, a context without the
  capability, a wrong content digest and an unapproved resource id are
  refused by the facade before the policy reader or any process.
- **Lost lease.** `revokeAll` while the fake agent holds: the child is
  terminated, `exit.stoppedBy === 'authority'`, the turn outcome is
  `interrupted`, the journal attempt is `cancelled`.
- **Replay and restart.** The same key and content is `replayed` with one
  process run; different content is `idempotency-conflict`. A journal file
  with a `dispatched` attempt and no end (what a crashed host leaves) loads
  as `unknown`; `submit` with that key answers `unknown / outcome-unknown`
  and runs nothing; `cancel` answers `unknown`.
- **Lock and standalone.** An enrolled data directory started with no
  authority is `enrolled-unavailable`: `submit` answers `unavailable /
runtime-unavailable`, nothing runs, the attempt is journaled `failed` with
  `managed-unavailable`, `identity` reports the binding state with no
  authority id, and an unmanaged `turns.send` still runs. In the unit tests
  the binding refuses to enroll or unenroll on a lost lock, treats a corrupt
  or tampered record as unreadable (unavailable), and keeps an alternate
  data directory under an enrolled production directory enrolled. A closed
  runtime answers `host-unavailable` on a managed write.

Provider routes: `managed` is `implemented` on the child-process route of
every provider with a standalone launch (note names the spawn admission and
the unqualified provider-internal effects), `unsupported` on Codex
app-server, OpenCode server, PTY and SSH. The run operations are left at
`implemented` rather than `locally-verified` on purpose: the real local sink
(the spawn) was exercised, but the decision came from an injected table, and
promotion is for the paired exercise (phase 04) to decide once a real
authority producer answers. A peer that negotiates at the default minimum is
therefore still refused `runs.submit`; one that asks for `implemented` is
activated and then meets `unavailable` on a host with no authority attached.
