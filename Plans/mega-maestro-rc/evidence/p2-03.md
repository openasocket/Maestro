## The per-provider permission-mode table

Built from the ceiling of MRC2-03-01 by a scratch test that imports the real
rules (`permissionVocabularyOf`, `managedPermissionModeProblem`,
`managedArgsProblems`, `buildAgentArgs` under `managedCeiling`,
`cliRequestedPermissionMode`, `codexSandboxCeiling`, `providerRouteSupport`)
over `AGENT_DEFINITIONS`, parked at
`Working/p2-03-08/scratch-permission-table.test.ts.txt` (1 test, exit 0,
output `permission-table.json`). For every defined provider but the internal
terminal, the real batch argument set of each requested mode (`readonly`,
`standard`, `full`) was measured under a ceiling pinning none, `readonly`,
`standard` and `full`: the mode check first, then the flag check on the
resulting arguments; the builder's throw and the plan's mode problem agreed on
every one of the 144 cells. `commandLineReads` is what
`cliRequestedPermissionMode()` reads back off that command line.

Read-only words: **enforced** (`readOnlyCliEnforced: true` with flags the
pin demands), **enforced-by-default** (`true` with no flag; Factory Droid's
`exec`), **accepted** (`false` with a flag the provider takes but does not
enforce; a `readonly` pin refuses the provider by name rather than trusting
the flag), **none** (no flag, no enforcement). Full-access words: **flag**
(measured on the command line), **env-only** (OpenCode's
`OPENCODE_CONFIG_CONTENT`, invisible to the argument check, held at the
request level only), **flagless** (Pi, Oh My Pi: held at the request level
only). `std@std` is a `standard` request under a `standard` pin, `ro@ro` a
`readonly` request under a `readonly` pin, `full@std` a `full` request under
a `standard` pin; `cli(std)` is what the command line of a `standard` request
reads back.

Every `full` request is refused by mode under `standard` and `readonly` for
every provider, and every request is admitted under no pin and under `full`.
Every `readonly` request is admitted under every pin for the nine providers
whose read-only mode the command line enforces. The Codex sandbox follows the
same pin: `readonly` is `read-only`, `standard` is `workspace-write`, `full`
and none leave it unpinned.

### Findings the table records

- **A `standard` batch request fits under a `standard` pin for four providers
  only** (`claude-code`, `pi`, `omp`, `opencode`). The other eight (`codex`,
  `gemini-cli`, `antigravity`, `qwen3-coder`, `hermes`, `factory-droid`,
  `copilot-cli`, `grok`) put a full-access flag on their own `standard`
  argument set through `batchModeArgs`, so the command line asks for full
  access whatever the mode label says, the CLI reads it back as `full`, and
  the ceiling refuses the flag by name. Only a `readonly` request of those
  providers fits under a `standard` pin. This generalizes the Codex finding of
  MRC2-03-03A; closing it means a `standard` headless argument set without
  the bypass per provider, a definition change that alters the unmanaged
  default and was not made in P2-03.
- **A `readonly` pin refuses three providers** rather than trusting a label:
  `gemini-cli`, whose read-only arguments are `-y` (a full-access flag, refused
  by name); `antigravity`, whose `--sandbox` is accepted but not enforced
  (`readOnlyCliEnforced: false`); `hermes`, which has no read-only flag at
  all. `supportsReadOnlyMode` in the capability table agrees with
  `readOnlyCliEnforced` for every provider but `qwen3-coder` (capability
  `false`, enforced `true` via `--approval-mode plan`); the ceiling reads the
  definition, as MRC2-03-01 chose.
- **A `full` request leaves no flag for three providers** (`pi`, `omp`:
  flagless; `opencode`: env-only), so it is held at the request level
  (`buildAgentArgs`, the launch plan, the desktop handler) and a CLI surface
  reads the same command line back as `standard`. OpenCode's
  `OPENCODE_CONFIG_CONTENT` with `"*": "allow"` is set by its definition in
  every mode but read-only and is not a name the environment ceiling strips,
  so a `standard` OpenCode turn under a `standard` pin runs with that blanket
  allow: the ceiling holds the named mode, not the effect.
- **Enforced versus accepted** is therefore two columns in the matrix: the
  read-only word (what the command line enforces) and the full-access
  mechanism (whether the ceiling can see the request on the command line at
  all). A flag the ceiling refuses is refused by name on every provider that
  carries it, including the static flags a provider does not itself declare
  (`staticFlagsAlsoRefused`).

`codex-app-server`, `opencode-server` and `ssh`. P2-03 adds ceiling
